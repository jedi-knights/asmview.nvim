1. INTRO                                                        *asmview-intro*

asmview.nvim compiles the function surrounding the cursor (or an explicit
range) to assembly and shows the result in a right-side vertical split.
Supports C, C++, Rust, and Go.

As you navigate the source buffer, the asm lines that correspond to the
current source line are highlighted on the right. See |asmview-line-sync|.

==============================================================================
2. REQUIREMENTS                                          *asmview-requirements*

- Neovim >= 0.10
- One of `cc`, `c++`, `rustc`, `go` on $PATH, depending on the language
- Optional: `c++filt`, `rustfilt` for symbol demangling
- Optional: a `compile_commands.json` for C/C++ project flags

==============================================================================
3. SETUP                                                        *asmview-setup*

                                                            *asmview.setup()*
require("asmview").setup({opts})

{opts} is a table matching |asmview-config|. Omitted fields fall back to the
documented defaults. Calling setup() multiple times is safe; the last call
wins.

==============================================================================
4. COMMANDS                                                  *asmview-commands*

                                                                  *:Asm*
:[range]Asm
    Compile and show assembly. With no range, uses the function enclosing the
    cursor. With `:'<,'>Asm` or any explicit range of 2+ lines, uses those
    lines verbatim. Opens a right-side vertical split holding the asm
    buffer; focus stays in the source window.

==============================================================================
5. MAPPINGS                                                  *asmview-mappings*

                                                       *<Plug>(AsmView)*
<Plug>(AsmView)
    In normal mode, run against the function at the cursor. In visual mode,
    run against the selection. asmview does not auto-bind this; map it in
    your config:
>
    vim.keymap.set({ "n", "x" }, "<leader>a", "<Plug>(AsmView)")
<

==============================================================================
6. WINDOW KEYS                                            *asmview-window-keys*

Buffer-local maps inside the asm window (customize via `keymaps` in setup).
Move focus into the asm vsplit first (e.g. CTRL-W l) to use them:

  `+`   increase optimization level (clamped at the end of `opt_levels`)
  `-`   decrease optimization level
  `R`   rerun the compiler with the current parameters
  `q`   close the vsplit (the asm buffer is wiped; source stays)

==============================================================================
7. SOURCE LINE SYNC                                        *asmview-line-sync*

                                                       *AsmviewSourceLine*
While the asm vsplit is open, every time the cursor moves in the source
buffer, the asm lines mapped to that source line are highlighted via the
`AsmviewSourceLine` highlight group. The group is defined with
`default = true` and links to `CursorLine`, so colorschemes may override it:
>
    vim.api.nvim_set_hl(0, "AsmviewSourceLine", { bg = "#2d2d4a" })
<

How the mapping is built:

- C / C++ : asmview injects `-g1` (minimal DWARF debug info). gcc / clang
  emit `.file` + `.loc` directives that identify the source line for each
  asm block.
- Rust    : asmview injects `-C debuginfo=1`. rustc emits the same gas
  `.loc` form.
- Go      : `go tool compile -S` already prefixes each instruction with
  `(file:line)`. No flag change is needed.

To disable debug info (and therefore line sync), override the injection via
`compilers.<lang>.extra_args` — the last `-g*` / `-C debuginfo=*` wins:
>
    require("asmview").setup({
      compilers = { c = { cmd = "cc", extra_args = { "-g0" } } },
    })
<

If a source line maps to more than 64 asm lines (hot inlined loops), the
first 64 are highlighted and the last gets a `[+N more]` virtual-text tag.

==============================================================================
8. CONFIGURATION                                              *asmview-config*

Defaults: >

    {
      compilers = {
        c    = { cmd = "cc",    extra_args = {} },
        cpp  = { cmd = "c++",   extra_args = {} },
        rust = { cmd = "rustc", extra_args = {} },
        go   = { cmd = "go",    extra_args = {} },
      },
      opt_levels = { "0", "1", "2", "3", "s", "z" },
      default_opt = "2",
      syntax = "intel",
      demangle = true,
      use_compile_commands = true,
      compile_commands_search_depth = 6,
      -- `float` is accepted for backward compatibility and currently
      -- ignored. The asm view is a vertical split as of 0.3.0.
      float = {
        width_ratio = 0.8,
        height_ratio = 0.8,
        border = "rounded",
      },
      keymaps = {
        increase_opt = "+",
        decrease_opt = "-",
        rerun = "R",
        close = "q",
      },
    }
<

==============================================================================
9. compile_commands.json                            *asmview-compile-commands*

For C and C++ sources only, asmview walks up from the source file (capped at
`compile_commands_search_depth` hops) looking for `compile_commands.json`. If
found, it uses the matching entry's flags, stripping `argv[0]`, `-c`, `-S`,
any `-O*`, `-o <path>`, and the input file itself. The remaining flags are
appended before `-S` and the input file. `-g1` is prepended first so the
`.loc` directives powering |asmview-line-sync| are always present (users can
override via `cfg.compilers.<lang>.extra_args`).

For Go buffers, asmview writes a self-contained temp module (`go.mod` +
`snippet.go`) that forces `package main`, prepends the buffer's `import`
block, and appends a `func main() {}` stub when missing. Assembly is
captured from the gc compiler's stderr. opt_level collapses to a two-state
toggle: `"0"` -> `-N -l` (no optimization, no inlining); anything else
leaves the gc optimizer on. Third-party imports resolve via GOPATH,
module proxy, or vendor directory, the same way `go build` does.
